    ```bash
    python3 ${CLAUDE_PLUGIN_ROOT:-$HOME/.claude/plugins/marketplaces/claude-supervisor}/scripts/manager-predispatch.py --vault "<vault-root>" --subject "<subject>" --write-verdicts <<'VERDICTS'
    {"<task name>": {"verdict": "<ready|repairable|needs-you|unfixable|below-bar|reframe|stale|blocked>", "score": <int|null>, "content_key": "<the key its Audit block reported>", "reason": "<the auditor's own words — required on needs-you|unfixable|below-bar|reframe, omitted otherwise>", "audited_at": "<ISO8601>"}}
    VERDICTS
    ```

    It prints the path it wrote, and refuses a malformed cache rather than writing one that cannot be read back. ⚠️ **`content_key` is required on every entry** — the invalidation rule is clause (1)'s and lives in its `<constraints>`; this writer enforces it by refusing an entry that carries no key, because a keyless entry cannot be matched against that rule and would read back as a cache hit forever. ⚠️ **`score` may be null** — `blocked` rows carry none. ⚠️ **`reason` is required on `needs-you`, `unfixable`, `below-bar` and `reframe`, and omitted on every other verdict** — those four are the verdicts whose act hands the operator the auditor's **own words** (the `UNFIXABLE:` grounds; the posted card's `--context` gaps), and the store is the only place those words survive a tick: a cache hit spends no dispatch, so a `needs-you` row cached without its reason can never render its grounds again and the next leg re-derives text it already had. Pass it **verbatim from the leg's `Audit` block**, never a summary of it — the writer refuses an entry that is one of those verdicts and carries no reason, so an omission refuses the whole write and the previous cache stands. ⚠️ **The requirement is on a *fresh audit*, not on the schema** — the writer compares each entry's `content_key` against the cache already on disk, and an entry whose key is unchanged is a **carry-forward**: its verdict was decided before the field existed, there is no audit left to re-derive the auditor's words from, and backfilling is out of scope, so it is accepted and the writer names it on stderr. ⚠️ **Without that distinction a single legacy entry bricks the whole cache** — measured 2026-10-02, four of five caches held one, so every write for those subjects was refused, the cache went stale, and the *next* tick audited cold: the 27-dispatch / 29-minute cost the cache exists to remove. ⚠️ **Never drop a legacy row to make a write succeed** — it is carried, not discarded, and it re-audits and gains a reason the first time its file changes. ⚠️ **And ask which copy the *script path* resolves to, never which version the session is on — the two are refreshed by different events.** The call above resolves `manager-predispatch.py` from disk **at invocation time** (`make update` moves the clone; `claude plugin update` populates the cache), while this command body was read **when the session started** and does not change under it. So a running session can be executing a **newer writer than the doc it is reading**, and the two can disagree about whether a legacy row is refused: the doc lag is bounded by the session, the script lag by the clone. ⚠️ **The dangerous state is new writer + old doc** — a session reading the pre-fix text expects a refusal that will not come, and may pre-emptively drop a row the writer would have carried, reintroducing by doc lag the loss the fix removes. The rule above holds in every state: carried, not discarded. ⚠️ **Key each entry off the ROW FILE's own title — never off the rendered `Audit` table.** Read the row's title from disk and use it as the JSON key; the leg elides names to `…` of its own accord — the `Audit` block is a per-row line format and defines **no width**, so nothing in it asks for the abbreviation — so a key copied from that render is either refused outright (the writer rejects **any** key carrying `…`) or — if the elided remainder is guessed — stored under a title no later tick will ever match, which reads as a cold audit rather than as a bad write. ⚠️ **This instruction used to say the opposite** (*"pass each row's key verbatim from its `Audit` block"*), and that is the cause of the stale titles this refusal exists to stop: the block is a *render*, and the caller is the only party that can read the row itself. ⚠️ **The measurement is not restated here** — it lives once with `ABBREVIATION_MARKER` in `scripts/manager-predispatch.py`, so a correction has one landing site rather than one per copy. The writer re-keys a name it can resolve onto the file's own basename, so a title read from disk is always right and a name invented here never is. ⚠️ **Persist only the rows the leg actually reported**, and never merge in rows from an earlier tick: a stale entry outlives the audit that produced it. ⚠️ **A refused write leaves the previous cache untouched** — the file is replaced atomically, so a bad stage cannot truncate a good cache.
