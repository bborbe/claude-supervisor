# Readings

When: every tick, **before** the sweep dispatch

⚠️ **A firing that lands while the previous round is still in flight is ABSORBED, never run — and that is a precondition on this whole step, not a reading within it.** When the previous round is still in flight, take **no** reading below, sweep nothing, dispatch nothing and write nothing: print one line naming the round still in flight — `ABSORBED  <subject>  in flight: <sweep reader|drive leg>  re-armed <n>s` — then re-arm for the next interval and end the turn. ⚠️ **The line is pinned to that shape, not left to the manager's phrasing** — the middle field names the leg that is *actually* in flight, so a reader and a `grep` can tell an absorbed firing from an ordinary quiet tick. **Never sweep anyway.** Rationale: runbook § Command rationale — maintained.

⚠️ **Each of the round's three writes belongs to the round that PRODUCED its input, never to the round that is current when the input arrives.**
- **The store save (`--save`)** — the round that **dispatched the sweep reader**. `--save` reads back the payload and the bucket sets *that reader* wrote, at per-subject paths, so a later round's reader overwrites them and a save by the later round records its data under the earlier round's provenance. Call shape and traps: `commands/steps/goal-sweep.md` — never restated here.
- **The verdicts-cache write (`--write-verdicts`)** — the round that **dispatched the drive leg**, persisting only the rows that leg reported. Home: `commands/steps/goal-drive.md`.
- **The topic-page write-back** — the round whose **own sweep produced the `noop: false` decision**, decided at the tail from that sweep's result and never from the head's placeholder. Home: `commands/steps/round-tail.md`.

⚠️ **A late leg's `Audit` block is DROPPED — never persisted, never merged, never superseded.** There is nothing for it to supersede, and its `content_key` is keyed to the row file's state **at audit time**, so a late block's keys may already be stale. Merging is the one thing `commands/steps/goal-drive.md` already forbids in words — *"never merge in rows from an earlier tick: a stale entry outlives the audit that produced it"* — so a dropped block costs one re-audit on the next round and cannot corrupt the cache.

⚠️ **This rule has exactly one home and it is this file.** A per-round rule placed in the arm is read **once** and never again; one placed in the round (`commands/goal-drive.md`) contradicts that file's own law (*"The rules do not live here, and that is deliberate"*). `scripts/check-round-overlap.py` asserts the single home and this file's every-tick reach.

1. **Open the round's receipt — first, before any read.** `python3 ${CLAUDE_PLUGIN_ROOT:-$HOME/.claude/plugins/marketplaces/claude-supervisor}/scripts/manager-receipt.py --start --topic "<subject>"`. This step is the first to run after the subject resolves, so this is the round's head and the only place its window opens. ⚠️ **`--start` clears the fields**, so a round is judged only on artifacts it produced itself, never on a previous round's. ⚠️ **The readings agent never runs `--start`** — a second call would clear what this round has already recorded. Rule, the record calls and the tail check: `commands/steps/round-tail.md` step 8.

2. **Delegate the four verdict families.** Dispatch:

`Task(subagent_type: "supervisor:round-readings-reader", prompt: <tracked path + subject + vault root + clamped interval seconds + timestamp>)`

The plugin prefix is required — a bare `round-readings-reader` resolves to a personal `~/.claude/agents/` copy. The agent (Sonnet) runs `scripts/round-readings.py` over the tracked set, records the `readings` field on the receipt, verifies the document's four families, and returns a **≤ 1 KB `key=value` hand-back** — the family counts plus the `payload=` path. It owns the traps (the feed's 20-row cap, the newest-`Stop` tie-break, `unread` never folded into a negative) — read them in `agents/round-readings-reader.md`; this step does not restate them. ⚠️ **Keep the `payload=` path** — the sweep reader refuses to render without the document behind it, and the tail's receipt check reads the record the agent made.

⚠️ **The counts are the hand-back; the per-row verdicts ride the payload.** The sweep dispatch's four map slots (liveness, in-flight, feed, external wait) are filled **from that document** — read it once and render them, never re-derive them from a fresh probe. ⚠️ **The document is the authority either way:** the sweep reader re-reads the same file as its input 16 and lets it win over the maps where the two disagree, so a map you render from anything else is a second reading waiting to drift.

⚠️ **When the delegation returns no usable hand-back** — it errored, came back empty, or resolved to something that returned no hand-back — run the same command yourself for this round, record it the same way, and carry on. Trigger on the missing hand-back, never on a matched error string.

⚠️ **A tracked set that resolved to no task is a REFUSED round, never a quiet one.** The readings agent reads the document's `resolution.state` first: `unresolved` (members were declared, none admitted a task) and `empty` (no members at all) both hand back `readings=REFUSED`, and this round records nothing. Measured 2026-11-08 (Development Pipeline Throughput): a tracked set of 38 vault-relative page paths resolved to zero rows and the document rendered `clear=38 · none=38` for 543 real task rows it never read — the most reassuring possible rendering of "I could not resolve a single task". ⚠️ **The earlier guard is the resolve step's `--compare-tracked` exit 11 (`caller-format`)** — a set sharing no name with the gate's membership refuses the round before this step runs. ⚠️ **Never re-run the leg to obtain a document after either refusal** — a refusal is not a degradation, and a fabricated table is what the sweep reader then renders as a completed sweep.

4. **⚠️ Write no reading into the dispatch that you have not taken this tick — and never batch a read with the dispatch that consumes it.** A **reading** is any value the prompt states as current: a feed count, a roster line, a liveness verdict, a task count. If a read's output is needed by a dispatch, the read **completes before the prompt is authored** — the read and the dispatch are **not** emitted in one message, because a prompt written in the same message as its own input has no output to quote and fills the slot from the previous tick instead. ⚠️ **A stale carry is worse than an omitted field:** an omission is visibly missing and the reader reports it as a caller bug, while a stale value has the same shape, position and confidence as a fresh one, so it silently disables the check it feeds. **When the read has not completed, leave the slot unstated** — never fill it from a prior tick.
