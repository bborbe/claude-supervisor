# Re-arm

When: every tick — arm `ScheduleWakeup` FIRST, before the read half

- **Re-arm FIRST — before the read half, not after it:** `ScheduleWakeup` with the `/supervisor:fleet-drive --interval <N>m` prompt — **name the ROUND, never the arm** — at the **clamped** interval. Default **15 min**; floor **15 min** — a below-floor value is **clamped up and announced** (`⚠️ --interval 5m is below the 15m floor — clamped to 15m`), never rejected. **Never tighter than 15 min, never self-re-invoking** — cadence belongs to the scheduler. ⚠️ **It belongs at the head of the round:** `ScheduleWakeup` is **one-shot per call**, so a long round (a drive leg, an escalation, a gate relay) never reaches an end-of-round re-arm and the loop then stops **silently**. Arming first makes a missed re-arm **impossible**; a round that later discovers a reason to slow down or stop re-arms again at that point. ⚠️ **`noop` is required by `ScheduleWakeup` and cannot be honest at the head** — the round has not run yet — so arm with `noop: false`. ⚠️ **This side DOES keep a liveness record, and it is written here — at every round's head, beside the `ScheduleWakeup`.** It was previously absent "rather than added for symmetry", and that absence was not neutral: `scripts/answer-path-check.py` reads a session's registration, and a session it cannot find reads as having **no answer path**, so the spawn guard refused **every** headless spawn the Fleet Manager made (measured 2026-10-23). The fleet round genuinely answers headless workers' parked prompts — it runs the wrangler and watches the queue — so the record states a fact that was always true.

   ```bash
   python3 "${CLAUDE_PLUGIN_ROOT}/scripts/fleet-register.py" --vault "$(basename "$PWD")" \
     && python3 "${CLAUDE_PLUGIN_ROOT}/scripts/manager-liveness.py" --arm \
          --subject "Fleet Manager" --branch fleet --interval "<clamped-seconds>"
   ```

   ⚠️ **`&&`, not two independent lines, and the quoting is load-bearing.** A registration that is refused must NOT be followed by an arm: that is precisely the registered-nowhere-but-armed state this step exists to prevent. Unquoted, `--vault <vault>` parses as a `<` redirection and `--interval <clamped seconds>` splits at the space into a redirection plus a stray word — the block would not run at all. ⚠️ **`$(basename "$PWD")` is the vault source**, and it is the right one: the fleet session runs with a vault as its cwd (that is what `commands/open.md` Step 0 resolves too), and the value is stored on the registration and read back by `scripts/reset.py` and `scripts/who-needs-my-help.py` to scope the session — a guessed or omitted value files a registration those readers mis-scope. ⚠️ **If `fleet-register.py` exits 1** (a missing `CLAUDE_CODE_SESSION_ID`, an unwritable state dir) it prints `REFUSED\t<reason>`; report that line and **skip the arm** — the session has no answer path, so the round must say so rather than run headless spawns it cannot serve.

   ⚠️ **Both lines, in that order, and both are load-bearing.** `fleet-register.py` writes `~/.claude/state/worker-manager/<session-id>.json` — the registration `answer-path-check.py` gates on, idempotent and safe to rewrite every round. `--arm` writes the cadence that `--state` then classifies, so a session registered but never armed reads `UNARMED` and is refused exactly like an unregistered one. ⚠️ **The cadence expires**: `--state` calls it STALE past `interval + SLACK`, so an arm written once at the first round goes stale ~18 minutes later and every later spawn is refused again. This step is the round, so this is where it must be refreshed. ⚠️ **`--branch fleet` is its own tier**, not a stand-in for `goal` or `topic`: the Fleet Manager manages no subject page, and the slug `fleet--fleet-manager` is what keeps it out of those namespaces. The interval is the **clamped** one, in **seconds**, never the requested minutes. ⚠️ **A second `ScheduleWakeup` supersedes the first rather than stacking** — so a later re-arm in the same round is a correction, never a second loop.
