# Propose a manager

⚠️ **Hand-run only — no round routes here.** Removed from the fleet round's router table on 2026-10-29 by the operator's ruling: *"u should not recommend to open more goals, maybe only crashed managers."* A round that surfaces expansion work spends the operator's attention on goals nobody asked to open, so the round raises only the recovery signal (a manager that is live but lapsed) and this step is no longer reachable from it. It stays in the repo because a hand-run `--post` still works, and because `commands/steps/readings.md` and `commands/steps/goal-spawn.md` still cite it as the home of the `start manager` answer path.

When: a hand-run `--post` is wanted — run: `python3 $P/propose-managers.py --post`

Rationale: runbook § Propose a manager for an unmanaged goal — maintained.

- **A goal holding approved work and no live manager is a lapse the fleet surfaces itself.** The round's own classification is blind to it: the sweep classifies **live sessions**, so a goal whose work was approved and never opened has no session to sweep from, and the unmanaged-topic candidate covers the other half — a topic whose workers are live and whose manager is not. Neither reaches this case. Measured 2026-10-12: five approved planning tasks on goal *Read CDB Data Through Weldall (MVP)* (seibert-brogrammers) sat unmanaged until the operator noticed and pushed the Fleet Manager by hand.
- **Run the script — it owns the predicate, the ranking, the manager-match, the slot gate and the declined-ask state.** `python3 $P/propose-managers.py --post` posts at most one card per free manager slot. ⚠️ **Not one of those rules is restated here, and none may be re-derived at this call site** — a threshold, a count, a ranking or a set-difference written a second time is the second counter this repo's `check-*` guards exist to refuse. Read the script's header for what qualifies a goal and why the gate reads the cap it reads. `--json` prints the whole computation and never posts, for a diagnosis.
- ⚠️ **A declined ask is not re-posted — run `--compare` before `--post`.** The store's suppression is open-scoped, so an ANSWERED card is re-asked on the very next round unless the branch keeps its own state; the policy and its four arms have **one home**, `commands/steps/goal-under-target.md`'s declined-ask bullet, and this branch cites it rather than restating it. `python3 $P/propose-managers.py --compare` prints one verdict per candidate and posts nothing, exiting `0/10/3/2`: **`0` → every candidate is suppressed — print the `SUPPRESS:` lines and run no `--post`**; **`10` → an ask CHANGED — run `--post`, which carries `compare`'s `REPOST:` reason onto the card's `--context`**; **`3` → nothing has been declined yet — run `--post`**; **`2` → REFUSED, surface the line and do not read it as "no cards"**. ⚠️ **`--post` also compares internally**, so a caller that skips `--compare` still cannot re-ask — the state is authoritative, never the caller's discipline.
- **The card is an ASK, never an act.** Two options under a per-goal dedup key, both produced by the script. ⚠️ **This step never spawns.** Nothing opens until the operator answers, and the answer is read back with `attention-ask.py poll <item-id>` — the id the script prints on its `posted:` line.
- ⚠️ **Exit codes are the branch, and `2` is never read as `3`.** `0` posted one or more cards · `3` nothing to do (no qualifying goal, or no free slot — the script prints which) · **`2` REFUSED**. ⚠️ **Every `2` path prints its own reason to stderr and there is no single shape to expect** — an unreadable cap or board, a tasks dir that does not exist, a `--json --post` combination, a shared dedup key, a post that returned no item id, or a state file that is unreadable. **Surface the line the script printed**; never summarize it as "no cards". An unreadable input and an empty fleet must not render the same, and only the second is a fact about the fleet.
- ⚠️ **On `start manager`, the manager is spawned by the operator's naming.** Since 2026-10-23 a manager may also open one below it without a card (`docs/session-tiers.md` § The four tiers) — but this step still opens nothing on its own. The spawn recipe (`-n "<subject> Manager"`, the `orange` colour, the `unset` prefix) has its homes in `commands/open.md` § Step 2B (goal) and § Step 2C (topic); the answer handling — which subject, which vault, and the `/supervisor:goal-loop "<goal>"` that arms it — has one home in `the Fleet Manager Session runbook` § Propose a manager for an unmanaged goal. Read them there; this step restates neither. ⚠️ **Then clear the goal's snapshot** — `python3 $P/propose-managers.py --clear --goal "<goal>"`. A spent snapshot left in place would suppress a legitimate later ask for a goal that loses its manager.
- ⚠️ **On `not now`, nothing is spawned.** The snapshot `--post` already wrote is the answer's record, so this step writes nothing more and the next round suppresses an unchanged ask; a CHANGED ask re-posts by itself. Do not re-post the same goal by hand.
