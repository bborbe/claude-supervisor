# Spawn

When: the drive leg returned `To open` / `To resume` rows

Rationale: runbook § Command rationale — maintained.

1. **Author the task before you spawn on it** — via `/vault-cli:create-task` **passing `--docs-only` or `--code`** (the route you already know; passing it is what stops `create-task` asking). The wrapper dispatches `task-creator`, which emits `# Success Criteria`, `# Definition of Done`, `# Tasks`; then score it with `vault-cli:task-auditor`, before any spawn. Never hand-write task files. **Check before spawning:** `grep -cE '^# (Success Criteria|Definition of Done|Tasks)' <task-file>` returns 3 — that proves only that the three headings **exist**, never that they clear the bar. ⚠️ **A sub-bar score is not a disposition for you to choose — the readiness ladder decides the row.** Its four branches and thresholds have their single home in `${CLAUDE_PLUGIN_ROOT}/docs/fleet-surface.md` § Spawn a worker item 2 — **read them there and never restate them here.** A score you have not read against that ladder does not spawn; hand-sharpening the criteria to spawn anyway is not one of the ladder's branches. ⚠️ Do **not** chain `/vault-cli:plan-task` — `commands/create-task.md` forbids it.

   ⚠️ **`flag: true` is NOT a parked marker** — it marks a task the **operator wants picked up**, so a flagged row may be opened automatically and **provenance is not read here**: any setter counts and an absent one is no bar. The only bound after the flag is capacity. ⚠️ **Which surface reads `flag_set_by`, the rulings and the measured basis have one home — `${CLAUDE_PLUGIN_ROOT}/docs/fleet-surface.md` § Approval provenance; read them there and never restate them here.**

2. **Delegate the spawn decision.** Dispatch:

`Task(subagent_type: "supervisor:goal-spawn-reader", prompt: <the drive leg's handed-over rows + vault root + tasks dir + subject slug + timestamp>)`

The plugin prefix is required — a bare `goal-spawn-reader` resolves to a personal `~/.claude/agents/` copy. The agent (Sonnet) reads each row's task file and the session-hold store, applies the approval, parked, hold, role, dependency and cap gates, resolves the call shape (`mode`, `target`, `shipping`, `vault`, `cwd`, `prompt`), writes the per-row decision to its payload, and returns a **≤ 1 KB `key=value` hand-back**: one line per row under `open:` / `resume:` / `held:` / `refused:`, plus the cap reading and the `payload=` path. It owns the gate order and the per-field rules — read them in `agents/goal-spawn-reader.md`; this step does not restate them. ⚠️ **The readiness verdict is not its business and not re-opened here:** the drive leg released these rows, and its verdict governs — a `To open` row is never re-held on readiness grounds.

   ⚠️ **When the delegation returns no usable hand-back** — it errored, came back empty, or resolved to something that returned no hand-back — take the two fleet reads and the per-row frontmatter yourself for this round (`worker-sessions.py --count`, `worker-target.py`, then the task files), applying the same gates, and carry on. Trigger on the missing hand-back, never on a matched error string.

3. **Execute the rows it handed over — the spawn is yours, and so is the mode argument.** The agent decided each row and wrote its shape to the payload; **this** session creates the session. ⚠️ **A `held:` or `refused:` row is terminal for this tick** — print its line and spawn nothing. ⚠️ **A `truncated=<n>` greater than zero means `n` rows ride the payload only** — open `payload=` for those and execute them from it; the hand-back's own rows are the ones that fit its 1 KB cap. ⚠️ **Print every `warn:` line verbatim before its spawn** — the shape is `⚠️ target "<t>" is not eligible for "<task>": needs <disqualifier>`, and it is **Advisory, never a refusal**: it names the gap and leaves the decision here, never drops the `target`, never rewrites the row (`docs/fleet-surface.md` § Spawn a worker item 7). ⚠️ **The mode binding, both directions:** pass `mode: headless` → `interactive=false` and `mode: interactive` → `interactive=true` (`docs/fleet-surface.md` § Spawn a worker item 6). ⚠️ **The argument is never omitted on a row this step spawns** — an absent `mode:` is classified and written back below, so by spawn time the field exists; omitting it is the `mode_source=config` defect this leg exists to remove. ⚠️ **The row's `role` outranks its `mode:` field — `role: agent` is `headless` always** (operator ruling 2026-11-06: *"Agents can't be interactive. Only direct sessions can be interactive."*; `role: human` and `role: manager` are the only interactive tiers). Never spawn a `role: agent` row with `interactive=true`, and when the agent reports `mode_source=role-corrected` write the field back first — `vault-cli task set "<task>" mode headless` — then pass `interactive=false`. A row the agent reported `mode_source=classify` gets the field written back first — `vault-cli task set "<task>" mode <interactive|headless>` — then the argument.

   **`To resume`** → read the row's `mode:` off disk **first**, because the mode picks the path — then re-probe liveness (**the drive leg** probed at its hand-off site; the window since then is yours to close, and a stale probe here puts two writers on one conversation). ⚠️ **A row whose `mode:` is absent routes to path A** — path A passes `interactive=false` explicitly, so no config resolution is left open for a resume to inherit.
   - **`mode: headless`, or absent → path A**, the headless spawn: `mcp__supervisor__spawn_agent(prompt="<the next instruction>", resume="<session_id>", interactive=false, cwd="<the cwd the agent reported>", …)` — `cwd` is required and **not** inherited by a resume, and `resume` **requires** `interactive=false` (the pair is refused, never silently downgraded).
   - **`mode: interactive` → path B, and you execute it yourself**: `/supervisor:open "<task>"`. Its resume branch *is* the wezterm `--resume` path (`commands/open.md` § 3.1), and it already carries both guards this step needs — its own hold check, and a `session-liveness.py --check` that refuses `LIVE`/`UNKNOWN`/`AMBIGUOUS` and resumes only on `ABSENT`.
   ⚠️ **A refused path is terminal — never fall back to the other one.** A fallback is a second resume the gate never authorised, and it lands a worker under a stamp recording a resume that never took. Write `vault-cli task set "<task>" last_auto_resume "<ISO8601>"` only **after** the liveness instrument shows the resumed id **live** — `session-liveness.py --check <id>` exiting `0` — and write nothing on a refused, errored or aborted resume. ⚠️ **That instrument reads the session-heartbeat endpoint, not the session registry**, so a sentence naming the registry here is stale. ⚠️ **A path-B resume writes no ledger row, and that is this branch's one real cost:** such a worker **is** counted against the fleet spawn cap where a path-A resume is not (`docs/fleet-surface.md` § Spawn a worker item 5).

   **`To open`** → spawn with the hand-back's shape: `spawn_agent(prompt="/vault-cli:work-on-task \"<task>\"", vault="<vault>", label="<task>", [task="<task>"], [target="<target>"], [interactive=<bool>], [shipping])`. ⚠️ **On a `docker` / `k8s` row the call shape changes — `env`, `resume`, `policy`, `interactive`, `window_id`, `role` and `shipping` are refused, `task` is required, and the row's `mode:` is exempt from the mode binding** — `${CLAUDE_PLUGIN_ROOT}/docs/fleet-surface.md` § Spawn a worker **item 7 is that branch's single home; never hand-build it here.** ⚠️ **A row whose `mode:` is absent is resolved from `role`, never held** — the agent reports `mode_source=role` with the mode it resolved, and you write the field back before spawning (`docs/fleet-surface.md` § Spawn a worker item 6 — the mapping's single home; read it there and never restate it here); spawning without the argument is the `mode_source=config` defect this leg exists to remove. ⚠️ **There is no unread case left for `mode`** — a `role: agent` row is `headless` and a `human` / `manager` row is `interactive`, whatever the body says, so an absent `mode:` never holds a row. ⚠️ **Never route a `To open` row through a `Skill`-invoked `/supervisor:open`, and never fall back to the wezterm path** — for a *new* worker that path is a tab by construction, cannot produce a headless worker, and writes **no ledger row**. ⚠️ **This ban is scoped to `To open` and never reaches a `mode: interactive` `To resume` row** — that row's mode asks for a tab, which is exactly what path B produces. ⚠️ **At the soft cap nothing opens at all** — print the agent's `⏸️ CONCURRENCY LIMIT: <n> running, <limit> allowed` and pick the remainder up next sweep; **the HARD cap is never this tick's limit** and a manager never passes `operator_named`.

   **Confirm the spawn took**: no `{error}` returned and the task flips `status: in_progress`; **a headless worker has no pane**, so its liveness comes from **the transcript file's mtime advancing** — **not from `.status`** and **not from `last_message`** (null until the worker writes assistant text).
