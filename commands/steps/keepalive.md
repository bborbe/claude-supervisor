# Keep alive — the topic managers

When: every tick

⚠️ **This leg acts, and a read-only execution is not a run of it.** Both halves restart, resume,
record the resume and hand over the pane; a run that only prints `unactioned: <n>` has measured
nothing. It is one of the round's three acting legs, so the round's delegate rule carves it out —
a sub-agent may run it only with write tools (`commands/fleet-drive.md`, the delegate rule's
carve-out).

⚠️ **Gate this leg on its own debt — the `re-arm` step — and chain it, do not merely read it:**

```bash
python3 "${CLAUDE_PLUGIN_ROOT}/scripts/manager-receipt.py" --debt --subject "Fleet Manager" --branch fleet --only re-arm \
  && <run this leg>
```

Exit **12** = the arm is still owed: print the `debt:` lines, skip this leg, and **carry on with the round — the tail still runs**, because the tail's `--check` is what reports the round's verdict to the operator. Exit **0** = no debt this leg consumes, run it. ⚠️ **Exit 2 = the gate could not read or write the debt file** — it prints nothing to stdout, only a reason to stderr; skip the leg and print that reason, never read 2 as "no debt". ⚠️ **`--debt` judges the round in progress**, re-reading the receipt, so a round that already armed is not blocked by a debt it has paid. ⚠️ **The exit code is the gate, never the printed line** — a leg that reads only the text is satisfied by an empty read.

⚠️ **Why `--only re-arm`, and not the whole round's debt.** None of this leg's five procedures reads the digest — they read `topic-keepalive.py`, `topicless-goal-keepalive.py`, `park-event.py`, `park-nudge.py` and `worker-keepalive.py`. Gated on the whole round, the leg was stopped by a step it cannot consume whenever the round reached row 5b with the sweep reader (row 2) still running in the background: measured 2026-11-05 on the Fleet Manager, 2 of 25 gate calls printed `debt: digest` and exited 12 (03:13:29, 06:57:39 — the second one's digest recorded at 07:05:35, after the leg). `--only` scopes the exit code, never the record: the debt file still carries the digest, so `--check` at the tail and the unscoped legs (`drive.md`, `flagged-open.md`) are unchanged. This narrows the 2026-10-31 trade — *a topic-manager resume is not urgent enough to outrank the step the round owes* — to the one step this leg needs: a round that has not armed still skips it, and a round whose sweep is merely in flight no longer does.

1. **Dispatch the leg — this step no longer carries its procedures.** Dispatch:

   `Task(subagent_type: "supervisor:fleet-keepalive-actor", prompt: <vault root + this round's digest path + round timestamp + the plugin root (`${CLAUDE_PLUGIN_ROOT}`, resolved — the actor reads `commands/steps/keepalive-topicless-goals.md` under it) + the roster: one session-id<TAB>name line per live session, from python3 "${CLAUDE_PLUGIN_ROOT:-$HOME/.claude/plugins/marketplaces/claude-supervisor}/scripts/session-liveness.py" --list --json>)`

The agent (Sonnet) runs the five procedures — **restart a lapsed topic manager**, **restart a lapsed goal manager whose goal no topic declares** (`commands/steps/keepalive-topicless-goals.md`), **resume the park watches whose re-check has passed**, **resume a decision-parked worker whose wait cleared** (`agents/fleet-keepalive-actor.md` § 2b), **nudge a watcher past the park threshold**, **resume a worker whose session died**, **close a stood-down manager past its bound** (`commands/steps/keepalive-stood-down.md`) — acts on every verdict, and writes the leg's three digest counts itself (`lapsed-managers`, and `dead-workers` with its `--floor` / `--exact` label). It owns every population resolver, every script invocation and every `⚠️` guard; read them in `agents/fleet-keepalive-actor.md` — this step does not restate them.

2. **What this step does with the hand-back.** Print its act counts (`restarted`, `resumed`, `parked-due`, `nudged`, `undelivered`, `decision-resumed`), its population counts (`decision-candidates`), its per-list counts (`crash-loop=`, `cannot-tell=`) and its row lists (`crash-loop:`, `cannot-tell:`, `park-nudge:`) as the round's report — they are what the leg **did** this round. ⚠️ **They are not digest keys, and that is not a second home:** the four `unactioned:` readings that must survive the round are the digest's, rendered from item 14's `LEGS` section, and ⚠️ **never from the hand-back** — a count printed from here and absent from the digest is exactly the defect item 14 removes. ⚠️ **A `crash-loop-truncated=` or `cannot-tell-truncated=` greater than zero means that many rows of THAT list ride `payload=` only** — read that file, print the remainder verbatim, and reconcile each list as `printed + its own dropped count == its own count` (`crash-loop=`, `cannot-tell=`) as `docs/handback-contract.md` § The shape — the truncation exception — states. ⚠️ **`park-nudge:` is a single summary line and never truncates**, so it has no dropped count and no part in that arithmetic. ⚠️ **`dead-scan` is the label the digest write used** — `complete` = `--exact`, `incomplete` = `--floor` — and it is read here for exactly one thing: a hand-back whose `dead-workers` count and `dead-scan` label disagree with the digest's own `dead-workers` line is a failed write, reported as such and never rendered as a measurement. ⚠️ **When `dead-workers=not-run` no count was written, so no label applies: `dead-scan=—`** and the digest's own line carries the not-run reason — a `complete` or `incomplete` beside a `not-run` count is the failed write that read is for. ⚠️ **`legs=written` beside a `not-run` key is legitimate** — a `--not-run` reason that landed is a reading that landed; only `legs=UNKNOWN` means a write failed. ⚠️ **A failed write is reported, never swallowed.** `legs=UNKNOWN` means `fleet-legs.py` exited 2 and the digest could not be read or written (the sweep may not have written it yet); render `legs: UNKNOWN — <reason>` for this round, with `<reason>` taken from the hand-back's `legs-reason=`, and retry the record once the digest exists. ⚠️ **The reason comes from `legs-reason=`, never from the agent's prose** — the hand-back is the only channel that crosses the delegation boundary, and a `legs=UNKNOWN` with no `legs-reason=` leaves the dash empty. A reading that never landed must not read as a leg that never ran.
