# Render the output shape

When: every tick

  - **Global delta:** on progress, a 3–5 line chat delta; detail stays in task files.

⚠️ **This step is executed by `supervisor:fleet-round` (router row 20), and it writes a FILE — it never prints to chat and never asks the operator.** The render lands in `~/.claude/state/fleet-handback/<round>.render`; the manager prints that file verbatim **after** its row 19 tail, which is the only order that lets the tail's verdicts reach the operator's block (`docs/handback-contract.md` § Where the full payload goes). ⚠️ **Printing it here instead would land in a headless transcript nobody reads, and returning it in the hand-back would break the ≤ 1 KB cap.** ⚠️ **An empty render and an absent one are different:** if `--budget` exits 14 before this row runs, the file does not exist and the manager says the render was `not-run`; write nothing rather than an empty file.

⚠️ **No `AskUserQuestion` lives in this file any more.** Two items used to carry one; both now render the *material* for a question and leave the asking to the manager's **row 11**, which is the only row that may put one — a headless delegate that asked would park with nobody to answer. Where an item below says "ask", read *render the text that row 11 will ask*.

## Output shape

1. **Roster** — the marker line plus the box, rendered **exactly per Fleet Manager Session runbook (per-vault) § Sweep output — the fleet table** — the single source for frame, columns, widths and icons. Build it with `python3 $P/fleet-board.py --json | python3 $P/box-table.py`; never hand-draw it. Every tick prints the marker line; the box re-prints when a bucket moved, a session appeared or vanished, or a handoff was sent, plus a ~30-min heartbeat. If `/fleet-status` just printed the same box, reference it.

   Print one quantitative line with the marker: the colour census `python3 $P/fleet-colours.py --json`, read for `backlog` (green/blue/cyan) with `default` and `purple` reported apart.

   ⚠️ **Also print `workers: <live>/<target>` on the marker line, every round.** Read the live count with `python3 $P/worker-sessions.py --count` — live **worker sessions**: the spawn ledger joined to the registry **or** the heartbeat store (a worker with no registry entry — headless in-process, or cluster — answers through the heartbeat). ⚠️ **Not `live-workers.py`** (reads the headless heartbeat store, answers `0` while interactive workers are live), and not `--list | wc -l` on either (counts the empty-store sentence, answers `1`). A non-zero exit means the store could not be read; print `workers: unknown`, never `0`. ⚠️ **The registry alone is not the answer either** — `~/.claude/sessions/*.json` also holds the operator's own sessions and the managers, so it is read **only through the ledger join that excludes them**, never on its own; the `ListAgents` roster is not a count at all. The target is `spawn.maxWorkerSoft` in `~/.config/claude-supervisor/config.json`, whose single home is `${CLAUDE_PLUGIN_ROOT}/docs/fleet-surface.md` § Spawn a worker item 5 — **read the number there and never restate it here.** ⚠️ **Read it with its own instrument, every round — never from memory:** `python3 $P/worker-target.py` prints the resolved target and nothing else, and `--source` adds `default|config|env`. Print `workers: <live>/unlimited` when the key is `0`, and `workers: unknown` when the store cannot be read — never `0`. ⚠️ **The SOFT cap is the target; the HARD cap above it is NOT this leg's business.** `python3 $P/worker-target.py --hard` reads it, and this round must never use it as the target: the band between the two is the operator-named exemption, and **a fleet sweep never passes `operator_named`**, so its ceiling is the soft cap on every path it has.
   **Managers by closeness to their SCs** — read `~/.claude/state/goal-coverage/*.json` and print one ordered line `managers: <subject> <measured>/<boxes> · …`, highest measured fraction first. A manager with no file prints `<subject> unranked` — never infer an order from a missing file.
2. **`Next focus`** — the next-focus reading's block, rendered verbatim: the ranked rows each with its source citation (`<vault>/60 Periodic Notes/<Period>/<key>.md:<line>` for a planned row — the script prints the path it resolved, so it is absolute whenever `--vault` is; a due-today row cites its own task file instead, since no plan line names it), a `phase: todo` row as `needs your approval`, the `left for the next round (cap <n>)` line when more were ranked — **anonymous by design, and deliberately unlike the named proposal remainder**: the candidates are ONE ranking, so the line need only say the list is truncated and the next round re-ranks, while each proposal is a separate ASK that would otherwise vanish unasked, the `Proposed for this week's plan:` rows (at most the cap the block prints, each posted as its own card), and an `alerts: unread|unavailable` line when that read failed. ⚠️ **Never omitted** — a held round prints `Next focus: held — at target (<live>/<target>)`, an unreadable capacity store prints `Next focus: held — workers unknown`, and **any non-zero exit** — the script prints nothing to stdout and the reason to stderr, and it maps an unexpected failure to the same refusal rather than exiting 1 with a traceback — prints `Next focus: refused — <that reason>`, because a suppressed round, a refused read and a round that found nothing must never render the same.
3. **Classification** — the payload's non-progressing rows: `<name> [<id>] · <status> · <classification>`. Never print the `[ref]`.
4. **`📋 Open with the operator`** — the ledger, one line per open entry: kind · what · state · age. **Never omitted**; `(none open)` when empty.
5. **Needs-input** — the batch over the payload's BLOCKED set **plus the material this round's own rows 7 and 8 routed** (the `parks-routed` entries and any spawn routed instead of run), **rendered as text only**: the questions and their options are written here so the manager's **row 11** can put the `AskUserQuestion`; the delegate never asks. Per **Needs-input** in `${CLAUDE_PLUGIN_ROOT}/commands/steps/needs-input.md` for the batch's own shape and its `asked-ledger` claims, then the consolidated list beneath it: every open claim across every layer, in one list. **Never omitted** — `(none blocked)` when the payload's BLOCKED section is empty, and a subject one of those rules dropped prints that rule and its line.
6. **Escalation report** — Step 5's own findings, grouped cause-first, rendered exactly per `${CLAUDE_PLUGIN_ROOT}/commands/steps/escalate.md` (its member list, its omit-if-nothing rule, its **unverified** marking).
7. **Drive leg** — the agent's payload verbatim (its header line, rows, `ESCALATION`, the `Waiting on your keystroke` list, `LEDGER`), read at the `payload=` path its hand-back named, plus `Sent: <n>` with one line per recipient and `Skipped: <n>` with reasons. ⚠️ **A leg the debt gate skipped renders `drive leg: skipped — debt owed (<steps>)` (or `drive leg: skipped — gate refused (<reason>)` on exit 2) instead of the payload** — there is no hand-back to print, and the never-omitted rule here must not be read as requiring a fabricated one. Otherwise rendered exactly per `${CLAUDE_PLUGIN_ROOT}/commands/steps/drive.md` — including its rule that the `Waiting on your keystroke` list still prints on a round whose drive leg returned no usable report, so the section is never omitted on any round. **The `SHARE` block and its `share: <verified>/<detected> (<pct>%)` line print here too, from `drive-share.py`, and are never omitted** — `0/0 (n/a)` on a quiet round, `share: refused — <reason>` on a read that failed, and never a blank standing in for either. **The drafted-vs-sent line prints here too and is never omitted** — `nudges: drafted <N> · sent <M> · missing <N-M>`, from `check-drive-nudges-sent.py`, beside `Sent:` and never replaced by it: a round with `missing > 0` prints the line and reports a FAIL, so a round whose send leg never ran and a round that sent everything never render the same, and `Sent:` alone is what a round prints while its drafted recipients go un-nudged. **The freeable-tabs line prints here too and is never omitted** — `freeable-tabs: rows <N> · linkable <L> · acted <M> · missing <L-M> · refused: <token>=<n> · …`, from `check-freeable-tabs-acted.py` — the `refused:` tail counts the refusal tokens the round recorded, bucketed by the token's first word (`deferred 2026-…` as `deferred`), and prints `(none)` when it recorded none, so the token the record carries is actually observable, plus the step's own `freeable-tabs: rows <N> · closed <M> · refused <K> · skipped <J>` from the close step itself. ⚠️ **Both lines print, and they answer different questions** — the step's line says what the round did, the check's says what the payload demanded, and a round that prints only the first is exactly the 2026-11-12 round: it listed a freeable row with a resolved link, queued it as a reap, and reported itself complete. A round with `missing > 0` prints the check's line and reports a FAIL, so a round whose close step never ran and a round that closed everything never render the same.
8. **Read-only context sent this sweep** — what and to whom.
9. **Course-correction drafts awaiting approval** — exact text + target, rendered so **row 11** can put the approval question; the delegate renders the draft and never asks.
10. **Snapshot written** — path and `swept_at`.
11. **The round's debt** — `python3 $P/manager-receipt.py --debt --subject "Fleet Manager" --branch fleet`, its `debt: <step>` lines printed verbatim. ⚠️ **Branch on the EXIT CODE, never on empty output — `--debt` prints nothing on exit 0 AND on exit 2.** Exit 2 means the gate could not read or write the debt file (a state-dir failure, a permission problem); rendering it as `debt: none` would make a broken gate indistinguishable from a clean round, which is the same "a skip and a clean round must never render the same" property this item exists to protect. Render exit 2 as `debt: refused — <the stderr reason>`. ⚠️ **On exit 0 the script prints nothing** — `debt: none` is the ROUND's own render for that case, never script output; writing the item as "printed verbatim: … or `debt: none` on exit 0" invites a model to render an empty item and break the same item's next clause. ⚠️ **Never omitted** — a round that skipped a step and a round that skipped none must never render the same, and this line is the only one that survives the round which produced it (`<slug>.debt` is a file, not a render, so it still fires on the next round even when that round never runs its tail). ⚠️ **The same call is the legs' gate, not only a display** — the two non-sweep legs chain it as `--debt && <leg>` (`drive.md`; `keepalive.md` scopes it with `--only re-arm`, because its procedures never read the digest), and it **judges the round in progress** rather than the last round's verdict, which is what makes it a prevention: a round that skipped the sweep is blocked on its own receipt at row 5, and a round that already swept is not blocked by a debt it has paid. A file-only read would invert both.
